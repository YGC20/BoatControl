## 📦 3️⃣ 확인된 기술 사실

### 모델 형식 (중요)
- `detector_onnxruntime.cpp`는 입력 `"images"`(1×3×640×640), 출력 `"output0"`을 사용하고, 각 행을 `[x1, y1, x2, y2, score, class]`로 읽음 → **NMS가 모델 안에 포함된 `[1, N, 6]` 형식**을 가정. C++에 NMS 코드 없음.
- 따라서 일반 YOLOv8/YOLO11 export(`[1, 84, 8400]`), YOLOv5(`[1, 25200, 85]`)는 **그대로는 사용 불가**. NMS-free인 **YOLOv10**이 호환.
- **정정**: `report_20260907.md`에 따르면 YOLOv8n도 `nms=True`로 export하면 `[1,300,6]`이라 호환됨(당시 그 방식으로 `yolov8n.onnx`를 썼음). 안 되는 것은 NMS 없는 일반 export뿐.
- **half(FP16) export 금지**(입력이 float 고정), 입력 크기 고정 640.
- COCO의 `bottle` 클래스 번호는 39. 현재 코드는 **클래스 필터가 없어** boat가 사람·의자 등 모든 검출 중 최고 score를 따라감 → 필터 위치(detector / vision main / boat) 결정 필요.
- 물 위 병은 COCO 모델로는 성능이 약할 수 있어 수면 쓰레기 데이터로 **파인튜닝**이 결국 필요.

### ONNX Runtime / CMake
- Windows에서는 **onnxruntime-gpu 1.18.0** 사용(`report_20251102.md`). 코드는 CPU 기본 옵션이라 Linux는 **1.18.0 CPU 패키지**로 맞추는 것을 권장.
- `detector_onnxruntime.cpp`는 이미 `#ifdef _WIN32`로 모델 경로 처리가 분리되어 있어 **수정 불필요**. 막히는 곳은 `vision/CMakeLists.txt`의 `IMPORTED_IMPLIB`(.lib) / `IMPORTED_LOCATION`(.dll) Windows 고정뿐.
- `vision/CMakeLists.txt`의 `copy_directory ../../model` POST_BUILD는 **`model/` 폴더가 없으면 빌드 실패**(종료 코드 1 확인). 저장소 루트 `model/`은 현재 없음(`*.onnx`는 `.gitignore`).
- `vision`은 **카메라를 먼저 열고 모델을 로드**하므로 웹캠 없는 환경에서는 모델 로드 단계까지 확인 불가. 웹캠 없이는 빌드·링크·`ldd` 확인까지가 범위.

### 커널 모듈 / boat 쪽
- 저장소에 **Makefile이 없음**: `.gitignore`가 `Makefile`을 제외함. `report_20260910.md`에는 Makefile을 작성했고 탭 버그가 남았다고 기록되어 있으나, 현재 이 PC의 저장소에는 없음 → 실습 폴더/보드 쪽에 있는지 확인 필요.
- `motor_driver.c`, `echo_driver.c`는 `GPIO_BASE 905` 하드코딩. Zynq-7000의 gpiochip base는 커널 버전에 따라 다르며 보통 906(⚠️ 6️⃣).
- 커널 모듈은 전역 GPIO 번호(base + MIO), 유저 앱(`distance_sensor_dev.cpp`)은 libgpiod line offset(= MIO 번호)을 씀 → 번호 체계 통일 필요.
- 코드는 **libgpiod v1 API**(`gpiod_chip_open_by_number` 등)를 사용. 최신 Ubuntu의 `libgpiod-dev`는 v2일 수 있어 PC 컴파일이 안 될 수 있음. Yocto/PetaLinux는 보통 v1.6 계열.
- `echo_driver.c` 잠재 이슈(실센서 전 논리 검토 대상): 유저 앱이 trigger를 먼저 쏘고 `read()`를 호출하는데 `echo_read`가 read 시작 시점에 `measurement_ready = false`로 초기화 → 그 사이 에코가 도착하면 놓칠 수 있음. `have_rise` 잔존 값 영향도 확인 필요.
- 하드웨어 주의: HC-SR04 echo는 5V 출력 → Zynq MIO(3.3V)에 **레벨 변환/분압 필수**. 모터 드라이버 입력 로직 레벨도 확인.

4. **단계 3** 바인드 마운트(`-v`), 파일 소유권(root) 문제와 `-u $(id -u):$(id -g)`
5. **단계 4** Dockerfile(`FROM`/`WORKDIR`/`RUN`/`COPY`/`CMD`), 레이어 캐시, `.dockerignore`
6. **단계 5(실전)** YOLOv10n export 이미지를 직접 작성: 베이스 이미지, CPU torch 설치 순서, 캐시를 고려한 설치 순서, 결과 폴더 마운트, 가중치 재다운로드 방지, `CMD` vs 실행 시 명령. **통과 기준**: 컨테이너 실행 → `.onnx` 생성 → 입출력 shape 검증까지.
7. **단계 6(선택)** boat 크로스컴파일 컨테이너(`arm-linux-gnueabihf-g++` + CMake). 커널 모듈은 타깃 커널 헤더가 필요해 PetaLinux 환경과 함께 고려.
- 주의: 이미지는 **CPU 전용 태그** 선택(GPU 없음, CUDA 이미지는 수 GB), `latest` 대신 버전 태그, `docker system df`/`prune`으로 디스크 관리(지우기 전에 대상 확인).

### D. 하드웨어가 있어야 하는 작업
1. Digilent Zybo Z7-10/20용 PetaLinux BSP로 프로젝트 생성 (코어가 Z7-10인지 Z7-20인지 확인)
2. 모듈 2개·boat 앱 레시피 추가(`petalinux-create -t modules`), rootfs에 `libgpiod` 포함, LAN 직결용 **고정 IP** 설정
3. 실제 GPIO base 확인: `cat /sys/class/gpio/gpiochip*/label`(값이 `zynq_gpio`인 칩), `cat /sys/class/gpio/gpiochip*/base`, `cat /sys/kernel/debug/gpio`
4. 타깃 커널 버전에 맞춰 드라이버 API 점검(`class_create` 등), 필요 시 디바이스 트리에 GPIO 선언 + `gpiod_*` API로 전환(보류 항목)
5. 배선(Pmod JF, MIO 10~15 후보) — **레퍼런스 매뉴얼로 JF↔MIO 대응 확인**, 초음파 echo 레벨 변환
6. `boat` 크로스컴파일 → 보드로 전송 → `insmod` → `USE_HW_MOTOR=ON` / `USE_HW_DISTANCE=ON` 실장치 테스트
7. 웹캠 있는 환경에서 `vision` 실행: 모델 로드, 실제 추론, 화면에서 `cls:39` 확인
