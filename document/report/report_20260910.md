## ✅ 1️⃣ 결정 사항

- `report_20260908.md`에서 미결정으로 남겨뒀던 "초음파 센서 실장치 방식(libgpiod edge-event vs 커널 모듈)"을 **커널 모듈 방식**으로 확정.
  - 이유: 이번 프로젝트 이전에 진행한 임베디드 학습이 캐릭터 디바이스·ioctl·인터럽트 같은 **커널 모듈 위주**였음. "코드는 직접 작성"하는 게 목표라, 프로젝트 관점의 경량함(libgpiod)보다 본인이 막힘없이 짤 수 있는 패턴(커널 모듈)을 우선하기로 함.
  - 이 결정에 따라 **모터 제어도 같이 전환** — libgpiod 유저스페이스 4핀 직접 제어(`motor_controller_gpio.cpp`)를 캐릭터 디바이스 + ioctl 방식(`motor_driver.c`)으로 교체. 두 하드웨어(모터/초음파) 모두 같은 패러다임으로 통일해 유저 앱이 libgpiod와 커널 드라이버를 왔다갔다 하지 않게 함.
  - 단, 초음파 **trigger 펄스는 유저 앱이 직접** `libgpiod`로 쏘기로 함 — 정밀도가 필요한 건 echo 쪽 타이밍이지, trigger는 "최소 10us"만 넘기면 되는 느슨한 조건이라 커널까지 갈 필요 없다고 판단.
- GPIO 제어 API는 `~/Documents/share/code/zynq_code`의 초기 실습(`24_ledon_ioremap`, `26_ledon_ioctl`)이 쓰는 raw register `ioremap` 방식이 아니라, 후반 실습(`28_buttonint`, `31_iomultiplex`)의 **gpiolib 레거시 API**(`gpio_request`/`gpio_direction_output`/`gpio_set_value`/`gpio_to_irq`)로 결정.
  - PetaLinux가 `xgpiops` 드라이버로 Zynq PS GPIO를 이미 gpiochip으로 등록해두기 때문에, 레지스터 오프셋(DIRM/OEN/DATA)을 직접 계산할 필요가 없고 오조작으로 실물 모터가 오작동할 리스크도 없음.

## 📦 3️⃣ 파일별 구현 요약

### `drivers/motor_driver/motor_ioctl.h`
- 드라이버·앱 공유 계약 헤더. `common/detection_packet.h`가 vision↔boat를 잇는 것과 같은 역할.
- `motor_direction` enum 값을 `app/inc/motor_controller.h`의 `enum class Command`(Stop=0~Right=4)와 동일하게 맞춤.
- `MOTOR_SET_DIR = _IOW('M', 0, int)` 하나만 정의, `arg`는 포인터가 아니라 방향 값을 직접 전달.

### `drivers/motor_driver/motor_driver.c`
- `26_ledon_ioctl`의 cdev/ioctl 뼈대 + `28_buttonint`/`31_iomultiplex`의 gpiolib API 조합.
- 모터 4핀을 `gpio_request`+`gpio_direction_output`으로 확보, ioctl 핸들러에서 `Command`별로 4핀 조합 결정(기존 `motor_controller_gpio.cpp`의 조합 로직 그대로 이식 — LEFT/RIGHT는 좌우 반대로 돌려 제자리 회전).
- init 실패 시 이미 확보한 GPIO를 역순으로 해제하는 goto 체인 구성.

### `drivers/echo_driver/echo_driver.c`
- `28_buttonint/blocking_io_driver.c`가 뼈대. 다른 점: 이벤트 유무가 아니라 **rising→falling 두 엣지 사이의 시간차(pulse width)**를 구해야 함.
- echo 핀을 both-edge(`IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING`)로 `request_irq`, ISR에서 레벨로 rising/falling 구분, `ktime_get()`으로 타임스탬프.
- `read()`는 `wait_event_interruptible_timeout`(40ms)으로 블록 — 무한 대기 방지. 타임아웃/에러 시 유저 앱이 "장애물 없음"으로 처리하도록 음수/짧은 리턴.
- pulse width(us, `s64`)를 raw로 넘기고, cm 변환은 유저 앱 책임으로 분리.
- trigger 관련 코드 없음 — 유저 앱이 별도로 처리.

### `app/src/motor_controller_dev.cpp`
- `open("/dev/motor_driver", O_RDWR)` → `apply()`에서 `ioctl(fd, MOTOR_SET_DIR, cmd)`. 실패 시 `std::runtime_error`(기존 GPIO 버전의 에러 처리 원칙 유지). 소멸자는 `apply(Stop)` 먼저 호출 후 `close()`.

### `app/src/distance_sensor_dev.cpp`
- 생성자에서 libgpiod trigger 라인 1개 확보 + `/dev/echo_driver` open.
- `read_cm()`: trigger 라인 1→10us 대기→0 → `read(fd_echo, &pulse_us, ...)` → 실패 시 `kNoObstacleCm(999.0)` 리턴, 성공 시 `pulse_us * 0.017`로 cm 변환.

### `app/CMakeLists.txt`
- `USE_GPIOD` 단일 옵션을 `USE_HW_MOTOR`/`USE_HW_DISTANCE`로 분리(모터는 더 이상 libgpiod 불필요).
- `USE_HW_DISTANCE=ON`일 때만 libgpiod 링크(trigger 1핀용).
- include 경로에 `../drivers/motor_driver` 추가(`motor_ioctl.h` 참조), 공유 헤더 경로를 `../common` → `../../common`으로 수정(디렉토리 한 단계 깊어짐).
