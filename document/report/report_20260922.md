## 📦 3️⃣ 확인된 기술 사실

### 발견한 버그 (수정 전)
1. **`num_detections` 미검증 → 범위 밖 읽기 / 크래시**
   - `main.cpp`의 최고 score 순회 루프 상한이 네트워크에서 받은 `packet.num_detections`이고, `detections[]`는 8칸(`kMaxDetections`).
   - `udp_receiver.cpp`는 magic과 길이만 검사하고 `num_detections`는 검사하지 않음.
   - 결과: 값이 크면 배열 밖(스택)을 읽고, 65535에서는 **SIGSEGV로 boat 프로세스가 죽음**. 종료 시 정지 코드도 실행되지 않음. 같은 LAN의 이상 패킷 한 개로 재현.
   - 수정 위치 후보: (a) `UdpReceiver::receive()`에서 `num_detections > kMaxDetections`면 false 반환(무시), (b) main 루프 상한을 `min(num_detections, kMaxDetections)`로 제한. 미정(사용자가 직접 결정).
2. **길이 검사가 초과 길이를 못 걸러냄**: UDP `recvfrom`은 버퍼(204B)보다 큰 데이터그램을 잘라서 204를 반환 → `n != sizeof(packet)` 검사를 통과. 위험은 낮지만 의도와 다름.

### 테스트 관찰 시 주의점
- boat는 수신 타임아웃(200ms)마다 **랜덤 방향**을 출력하므로 "무시된 패킷 = 출력 없음"이 아님. 무시 여부는 "결정적인 내용(Left)의 패킷인데 결과가 Left 하나가 아님"으로 판정.
- 결정적 케이스는 시작 직후 랜덤 출력 1~2줄이 섞이므로 "기대 방향 ≥ 전송 횟수"로 판정.
- 패킷 간격은 수신 타임아웃보다 충분히 짧게(20ms) 보내야 랜덤이 끼지 않음.
- stub 거리 센서가 100cm 고정이라 **Stop(60cm 미만) 경로는 stub로 검증 불가**.
- boat 종료(SIGINT) 시 마지막에 `STOP`이 출력됨(정상). 테스트에서는 이 줄을 제외.

### 부수 관찰 (미조치)
- boat `main.cpp`의 `--port`는 `std::stoi`에 예외 처리·범위 검사가 없음(vision과 달리). 잘못된 입력 시 예외로 종료.
- 거리 `< 60cm`일 때 `continue`로 루프를 도는 동안 대기 없이 반복해 CPU를 계속 사용하고 UDP를 읽지 않음(실센서 단계에서 점검).
