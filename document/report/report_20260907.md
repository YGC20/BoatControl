## ✅ 1️⃣ 배경 및 결정 사항

기존 계획은 라즈베리파이 한 대에서 영상 처리(YOLO 추론) + 모터/초음파 제어를 모두 수행하는 구조였으나, 현재 여건상 다음과 같이 역할을 분리하기로 함.

| 장비 | 역할 |
|------|------|
| 노트북 (Windows, C++) | 웹캠 영상 캡처 + ONNX Runtime 추론 (`vision`) |
| 징크보드 (PetaLinux) | 탐지 결과 수신 + 모터 제어 + 초음파 장애물 회피 (`boat`) |

- 초음파 센서는 아직 실물이 없어 **코드는 작성하되 임시(더미) 값**을 사용한다.
- 두 장비는 **LAN 케이블(이더넷) 직결**로 연결한다. USB는 디버깅 콘솔/전원용으로만 사용.
- 통신 프로토콜은 **UDP 소켓**을 사용한다.
  - 이유: 매 프레임 최신 탐지 결과만 의미가 있고(오래된 값은 버려도 무방), 재전송·순서보장이 필요 없는 "덮어쓰기" 성격의 제어 데이터이므로 TCP보다 UDP의 저지연 특성이 적합함.
- 전송 데이터는 **raw 탐지 결과** (bbox 좌표, class, confidence)로 정함. 중심좌표 계산 및 주행 로직 판단은 수신 측(징크보드)에서 수행.

## 📦 3️⃣ 통신 포맷: `common/detection_packet.h`

```cpp
#pragma pack(push, 1)

struct DetectionEntry {
    std::int32_t class_id;
    float        score;
    float        x1, y1, x2, y2;   // 원본 프레임 픽셀 좌표
};

struct DetectionPacket {
    std::uint16_t magic = kDetectionPacketMagic; // 0xD5C1, 쓰레기 패킷 필터링용
    std::uint16_t frame_width;
    std::uint16_t frame_height;
    std::uint16_t num_detections;   // <= kMaxDetections(8)
    std::uint32_t frame_id;
    DetectionEntry detections[kMaxDetections];
};

#pragma pack(pop)
```

- 구조체를 그대로 `sendto`/`recvfrom` payload로 사용 (한 데이터그램 = 한 프레임).
- `frame_width/height`를 같이 보내서 수신 측이 하드코딩된 해상도 없이 중심좌표 계산 가능.
- **엔디안 주의**: x86 노트북과 ARM Cortex-A 기반 Zynq(PetaLinux, 기본 리틀엔디안)는 둘 다 리틀엔디안이라 지금 구성에선 문제없음. 추후 다른 아키텍처가 붙으면 바이트오더 변환 필요.

## 💻 4️⃣ 파일별 구현 가이드

### `vision/src/udp_sender.h` / `.cpp`
```cpp
class UdpSender {
public:
    UdpSender(const std::string& host, uint16_t port);
    ~UdpSender();
    bool send(const dsu::DetectionPacket& packet);
private:
    SOCKET sock_; // Windows=SOCKET, POSIX=int
};
```
- Windows(WinSock): `WSAStartup` → `socket(AF_INET, SOCK_DGRAM, 0)` → `sendto()`. 소멸자에서 `closesocket` + `WSACleanup`.
- `sendto`에 `sizeof(DetectionPacket)` 그대로 전달.
- CMake에서 `ws2_32.lib` 링크 필요.

### `vision/src/main.cpp` (웹캠 실시간 루프로 재작성)
기존 `<model> <image_path>` 1장 처리 방식 → 실시간 루프로 변경.

- 루프: `cap.read(frame)` → `det->infer(frame)` → 결과를 `DetectionPacket`에 채움

- `sender.send(packet)` 매 프레임 호출.
- `--host`, `--port`(기본 `dsu::kDefaultBoatPort`), `--camera` CLI 인자 파싱 권장.

### `boat/src/udp_receiver.h` / `.cpp`
- POSIX 소켓(`socket/bind/recvfrom`) — 징크보드는 리눅스라 WinSock 분기 불필요.
- **타임아웃 필수**: `setsockopt(SO_RCVTIMEO)`로 짧은 타임아웃(예 200ms) 설정. 없으면 패킷 미수신 시 `recvfrom`이 무한 블록되어 초음파 장애물 체크가 못 돎.
- 수신 성공 시 `magic` 필드 검증 후 불일치하면 버림.

### `boat/src/main.cpp` (Python `yolo_main.py` 제어 로직 이식)
1. `distance = sensor.read_cm(); if (distance < MIN_DISTANCE) { motor.apply(Stop); continue; }`
2. `receiver.recv(packet, timeout)` — 못 받으면 "타겟 없음" 취급 → `Right`(탐색 회전, Python `mc.RIGHT`와 동일).
3. 받았으면 `num_detections` 중 `score` 최댓값 1개 선택.
4. `x_center = (x1+x2)/2`, `frame_center = packet.frame_width/2`, `TOLERANCE = 80` (Python 값 그대로 이식).
5. 중심 근처 → `Forward`, 왼쪽 → `Left`, 오른쪽 → `Right`.
6. `motor.apply(cmd)`.

### `vision/inc/udp_sender.h` / `vision/src/udp_sender.cpp` 완성
초기 작성본에서 아래 문제들을 순차적으로 발견·수정:
- 생성자 인자로 받은 `host`/`port`를 안 쓰고 하드코딩된 매크로(`PORT 9000`, `DEVICE_IP ""`)를 쓰던 문제 → 생성자에서 `deviceAddr`(멤버, `SOCKADDR_IN`)에 저장하도록 변경
- `send()`가 `connect()`만 하고 실제 데이터를 전송하지 않던 문제 → `sendto()`로 실제 전송하도록 구현
- 실패 시 `this->~UdpSender()`를 직접 호출해 이중 소멸 위험이 있던 부분 제거
- `.cpp`에 잘못 들어가 있던 헤더가드, `<winsock.h>`/`WS2tcpip.h` 혼용 → `<winsock2.h>`로 정리
- 소멸자가 비어있어 리소스가 누수되던 문제, `WSAStartup` 실패 시 `sock_`이 미초기화 상태로 남던 문제 → `sock_` 초기화 및 `sock_ != INVALID_SOCKET` 가드로 해결

최종적으로 host/port 반영, `sendto()` 실전송, 초기화 실패 경로별 안전한 정리(cleanup)까지 확인 완료.

### `vision/src/detector_onnxruntime.cpp` 구현
`infer()`를 아래 순서로 채움 (레터박스 스케일/오프셋은 `LetterboxResult` 구조체로 반환해 후처리에서 재사용):
1. 레터박스 리사이즈 (640×640, 비율 유지 + 패딩)
2. BGR → RGB (`cv::cvtColor`)
3. 정규화 (0~255 → 0~1 float, `convertTo`) — YOLOv8은 mean/std 정규화 없이 스케일링만 필요
4. HWC → CHW 변환 (`cv::split` 후 채널 순서대로 이어붙임) + `Ort::Value::CreateTensor<float>`로 텐서 생성
5. `session_->Run()` 호출 (입력명 `"images"`, 출력명 `"output0"`)
6. 후처리: score 임계값(`0.25`) 필터링 → 레터박스 역변환(`(raw - offset) / scale`, `std::clamp`로 프레임 범위 제한) → `Detection` 벡터 반환. 정렬/`kMaxDetections` 캡핑은 설계대로 boat 쪽 책임으로 남겨둠(vision은 임계값 통과분 전부 반환).

구현 과정에서 오탈자(`frmae`→`frame`, `srcW`→`src_w`), `return` 누락, `y2` 대입 자리에 `x2`를 또 대입한 로직 버그, `const uchar*`→`float*` 잘못된 `reinterpret_cast`(→ `const float*`로 수정) 등을 단계별로 발견·수정.
